# fcrypt

Кроссплатформенная консольная утилита на C++17 для аутентифицированного
шифрования файлов паролем.

**Криптография:** Argon2id (RFC 9106) + ChaCha20-Poly1305 (RFC 8439).
Пароль не хранится ни в файле, ни в настройках. Восстановления пароля нет:
если пароль забыт, расшифровать данные невозможно.

> Абсолютной защиты не существует. Программа защищает **содержимое файла**
> от чтения и изменения без пароля при условии, что пароль достаточно
> стойкий, а компьютер пользователя не скомпрометирован. Подробности — в
> разделах «Модель угроз» и «Ограничения».

## Возможности

- Шифрование и расшифровка любых обычных файлов, включая пустые и большие.
- Argon2id с памятью 256 МиБ, 3 итерациями и 4 потоками по умолчанию.
- 32-байтовая случайная соль для каждого файла.
- Поточное шифрование блоками по 1 МиБ: большой файл не загружается в RAM целиком.
- Аутентификация каждого блока и заголовка; обнаруживаются изменение,
  перестановка блоков, усечение и добавление данных.
- Скрытый ввод пароля, подтверждение при шифровании, очистка пароля и ключа
  в памяти.
- Запись результата во временный файл и атомарная замена только после успеха.
- Существующий выходной файл не перезаписывается без `--force`.
- Поддержка путей Unicode в Windows.
- Полностью статическая сборка для Windows не требует OpenSSL DLL.
- Нет сетевого доступа, телеметрии и внешних зависимостей во время работы.

## Быстрый старт (Windows)

Готовый файл: `dist\fcrypt.exe` (Windows x64, статическая сборка).

```powershell
# Зашифровать. Пароль будет запрошен дважды и не отобразится.
.\dist\fcrypt.exe encrypt "C:\Docs\secret.pdf"

# Получится C:\Docs\secret.pdf.fcrypt
# Расшифровать в явно указанный файл
.\dist\fcrypt.exe decrypt "C:\Docs\secret.pdf.fcrypt" -o "C:\Docs\secret-restored.pdf"

# Если выходной файл уже существует, заменить его можно только с --force
.\dist\fcrypt.exe decrypt "C:\Docs\secret.pdf.fcrypt" -o "C:\Docs\secret.pdf" --force
```

По умолчанию:

- `encrypt` создаёт `<имя>.fcrypt`;
- `decrypt` удаляет расширение `.fcrypt`, иначе добавляет `.decrypted`;
- исходный файл **не** удаляется.

## Сборка

### Windows: MSYS2 UCRT64

Нужны 64-разрядный GCC и OpenSSL **3.2 или новее** (в OpenSSL 3.2 появился
Argon2id). В окружении MSYS2 UCRT64:

```bash
pacman -S --needed mingw-w64-ucrt-x86_64-gcc mingw-w64-ucrt-x86_64-openssl
```

Затем в PowerShell из каталога проекта:

```powershell
powershell -ExecutionPolicy Bypass -File .\build.ps1
```

Скрипт создаёт статический `dist\fcrypt.exe`. Для сборки с динамической
`libcrypto-3-x64.dll`:

```powershell
.\build.ps1 -Dynamic
```

### CMake

```bash
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build
```

На MinGW статическая сборка:

```bash
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release -DFCRYPT_STATIC=ON
cmake --build build
```

Под Linux нужен OpenSSL >= 3.2 (например, OpenSSL 3.5 из репозитория
дистрибутива или собранный вручную). В Ubuntu/Debian с OpenSSL 3.0 Argon2id
отсутствует, поэтому простая установка `libssl-dev` может не подойти.

## Использование

```text
fcrypt encrypt <входной_файл> [-o <выходной_файл>] [параметры]
fcrypt decrypt <входной_файл> [-o <выходной_файл>] [параметры]
```

Параметры:

| Параметр | Назначение |
|---|---|
| `-o`, `--output <файл>` | выходной файл |
| `-f`, `--force` | заменить существующий выходной файл |
| `--password-stdin` | прочитать пароль одной строкой из stdin (автоматизация) |
| `--allow-weak-password` | разрешить пароль короче 12 символов |
| `--kdf-memory <МиБ>` | память Argon2id, 8..1024 (по умолчанию 256) |
| `--kdf-time <N>` | итерации Argon2id, 1..16 (по умолчанию 3) |
| `--kdf-lanes <N>` | lanes Argon2id, 1..16 (по умолчанию 4) |
| `-h`, `--help` | справка |
| `--version` | версия |

Параметры KDF задаются только при шифровании. При расшифровке они читаются
из заголовка файла, поэтому достаточно помнить пароль.

### Пароль

- При шифровании требуется не менее 12 символов (можно обойти флагом
  `--allow-weak-password`, но это снижает защиту).
- Пароль учитывается как точная последовательность байтов: регистр, пробелы
  и Unicode-нормализация не изменяются. Вводите одинаково на всех системах.
- Рекомендуется длинная случайная парольная фраза, сгенерированная
  менеджером паролей, например 5–7 случайных слов.
- Пароль нельзя передать аргументом командной строки — это сделано
  намеренно, чтобы он не попал в историю команд.
- `--password-stdin` удобен для скриптов, но пересылайте пароль только через
  защищённый канал. При этом режиме подтверждение пароля не запрашивается.

### Коды возврата

- `0` — успех;
- `1` — ошибка аргументов, ввода-вывода или повреждённая структура файла;
- `2` — неверный пароль либо не прошла проверка подлинности данных.

## Криптографический дизайн

Подробный формат: [FORMAT.md](FORMAT.md).

1. Для каждого файла генерируются 32 байта соли и 8 байт префикса nonce
   криптографическим ГПСЧ OpenSSL.
2. Ключ 256 бит выводится Argon2id:

   - память 256 МиБ, 3 итерации, 4 lanes;
   - соль 32 байта;
   - associated data `fcrypt/v1/argon2id/file-key`;
   - ранняя очистка пароля внутри Argon2-контекста.

3. Файл шифруется ChaCha20-Poly1305 блоками по 1 МиБ. Для каждого блока:

   - nonce = 8-байтовый префикс файла || 32-битный номер блока;
   - AAD = заголовок (80 байт) || номер блока || признак последнего блока ||
     длина открытого текста блока;
   - тег Poly1305 — 16 байт.

4. Заголовок содержит версию формата, алгоритмы, параметры Argon2id, соль,
   префикс nonce и точный размер исходного файла. Заголовок не зашифрован,
   но аутентифицируется тегом каждого блока.
5. При расшифровке проверяются все теги, точный размер файла и отсутствие
   лишних данных. Только после успешной проверки последнего блока временный
   файл переименовывается в итоговый.
6. Пароль, ключ и буферы открытого текста очищаются при освобождении.
   Пароль сравнивается с подтверждением за постоянное время.

Ключ уникален для каждого файла благодаря случайной соли, даже если пароль
один и тот же. Nonce уникален внутри файла благодаря номеру блока.

## Модель угроз

Программа рассчитана на следующие сценарии:

- у злоумышленника есть только зашифрованный файл и параметры формата;
- он может изменять, переставлять, усекать блоки и добавлять данные;
- он пытается подобрать пароль офлайн.

В этих условиях:

- содержимое нельзя прочитать без пароля;
- любое изменение файла обнаруживается;
- перебор паролей сдерживается Argon2id (память и время), но не становится
  невозможным при слабом пароле;
- пароль нельзя «обойти», «сбросить» или восстановить по файлу.

## Ограничения

Ни одна программа не даёт абсолютной защиты. Важно понимать:

- **Пароль.** Стойкость определяется энтропией пароля. 12 символов — минимум
  политики, а не гарантия. Слабый пароль можно подобрать.
- **Скомпрометированный компьютер.** Keylogger, вредоносное ПО, отладчик,
  дамп памяти, доступ администратора или физический доступ к включённой
  машине позволяют получить пароль или открытые данные.
- **Метаданные.** В файловой системе видны имя, время создания и размер
  зашифрованного файла. Внутри формата открыто хранятся точный размер
  исходного файла, соль и параметры Argon2id. Имя исходного файла внутрь не
  записывается.
- **Исходный файл.** Он остаётся на диске после шифрования. Программа его не
  удаляет. Обычное удаление и перезапись не гарантируют уничтожение данных
  на SSD, в журналах ФС, снапшотах и облачных резервных копиях.
- **Временный файл при расшифровке.** До финальной проверки открытый текст
  может находиться во временном файле с правами текущего пользователя
  (на Unix — режим `0600`). При ошибке он удаляется, но при аварийном
  завершении процесса может остаться.
- **Память.** Буферы очищаются, но не блокируются в ОЗУ (`mlock` /
  `VirtualLock`). Привилегированный злоумышленник может успеть прочитать их
  или получить из swap/дампа.
- **Статическая сборка.** В неё вкомпилирована версия OpenSSL на момент
  сборки. При выходе обновлений безопасности программу нужно пересобрать.
  Динамическая сборка использует обновляемую `libcrypto` DLL.
- **Аудит.** Код не проходил независимый криптографический аудит. Для
  критичных данных используйте проверенные инструменты либо закажите аудит
  и тестирование этой реализации.
- Нет защиты от уничтожения файла, подмены приложения, атак на цепочку
  поставок, скрытых томов и отрицания наличия данных (deniability).

## Проверка

```powershell
powershell -ExecutionPolicy Bypass -File .\tests\test.ps1
```

Тесты проверяют пустой файл, границы блоков, Unicode-пути, неверный пароль,
повреждение данных и соли, усечение, добавление данных, перестановку блоков,
защиту существующего выхода, политику паролей и отсутствие временных файлов.
